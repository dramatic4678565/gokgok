Summary

Mosaic is a fully rebranded fork of Excalidraw, operated as a collaborative whiteboard. The core engine carries hundreds of thousands of lines of inherited code, but Mosaic has a small yet critical layer of its own: the branding pipeline, the upstream merge machinery, and the data-privacy guard.

The one thing to understand

Mosaic is a base onto which new Excalidraw code merges itself every six hours. So the question behind any change is always — “will this conflict with the next upstream merge?” The project's entire architecture is an answer to that one question.

Strengths

  • Automated upstream sync. A clean merge opens a PR and auto-merges; a conflict stops and opens an issue for a human. It never force-pushes anything.
  • Script-driven rebrand. The rename was applied by script, not by hand, so it can be re-verified and re-applied (node scripts/rebrand.cjs --test runs 70+ assertions).
  • Safe by default on data privacy. Every backend endpoint inherited from the fork was blanked out, so user data cannot silently reach Excalidraw's servers.
  • Sound render engineering. Three-canvas architecture, fractional indexing, bitmap caching, structural sharing.

What needs work

  • The docs build and its examples are stale — dev-docs bundles against an old published version of the package.
  • The Docker image pipeline is broken — .dockerignore excludes the app source.
  • Two packages have a genuine circular dependency.
  • Several automated guards are inactive — the pre-commit hook is empty.
